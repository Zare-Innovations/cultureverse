# CultureBowl 2026 launch site

Production site for allthingsculturebowl.com, built from the design export in `design/`
(see `design/README.md` for the artboard map, tokens and copy rules).

Stack: Next.js 15 (App Router, TypeScript, `output: 'export'`), plain CSS (`styles/cb2.css`
is the shared design-system stylesheet, one CSS module per page), Golos Text and Cormorant
Garamond via `next/font/google`. Deployed on Vercel as a static export.

## Run

```bash
npm install
cp .env.example .env.local   # then fill in the values
npm run dev                  # http://localhost:3000
npm run build                # static export into out/
npx serve out                # serve the export locally
```

`next/font` downloads the Google Fonts at build time. Behind a proxy that Node's fetch
does not read, run the build with `NODE_USE_ENV_PROXY=1`.

## Environment

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_TICKETMASTER_URL` | Every "Get tickets" / "Tickets" button opens this in a new tab. Defaults to the `[CULTUREBOWL EVENT URL]` placeholder. |
| `NEXT_PUBLIC_FORM_ENDPOINT` | Receives the four forms as JSON `POST` bodies with a `form` field: `tap-in`, `exchnge`, `biggive`, `iconhonors`. Unset: the forms show their error line instead of a false success. |
| `NEXT_PUBLIC_SHOP_URL` | Where the Shop links go. Defaults to `/shop`, the built-in shop. An absolute URL sends every Shop link to an external store instead. |
| `NEXT_PUBLIC_SHOP_STORE_URL` | The Squarespace store that feeds `/shop` at build time and takes the sale (`lib/shop.ts`). Defaults to `https://www.shopallthingsculturebowl.com`. |
| `NEXT_PUBLIC_SHOP_COLLECTIONS` | The store's collection slugs to read, in order. Defaults to `apparel,hats`. |
| `NEXT_PUBLIC_HEADLINER_ANNOUNCED` | `true` switches the desktop Home hero to the announced variant (02-Home-Announced). Default off. |
| `NEXT_PUBLIC_EXPO_TICKETS_ON_SALE` | `true` once CultureExpo tickets go on sale: the Expo page swaps "Notify me" for "Get weekend tickets", adds ticket offers to its Event schema, and the Expo is labelled "Ticketed" instead of "Coming soon" on its page, the Cultureverse hub and the home stones. Default off. |
| `NEXT_PUBLIC_GA_ID` | GA4 measurement ID. `components/Analytics.tsx` renders the tag only when this is set. |

All of these are read at build time, so a change needs a new build. The shop catalog is not: on Vercel the shop pages re-read the store once a cached copy is five minutes old, so a product edit in Squarespace shows within minutes with no deploy. `npm run build:static` writes the fully static `out/` the preview and the verification scripts use.

## Launch files

`vercel.json` also sends `X-Robots-Tag: noindex, nofollow` on any `*.vercel.app` host, so the
deployment's own address stays out of search results until the real domain is attached.

- `PLACEHOLDERS.md` lists every bracketed placeholder and empty link with file and line, regenerated by `npm run placeholders`.
- `vercel.json` carries the security headers. Its Content-Security-Policy includes the form endpoint host and the analytics hosts, so after setting `NEXT_PUBLIC_FORM_ENDPOINT` or `NEXT_PUBLIC_GA_ID` run `npm run vercel-config` (reads the environment, then `.env.local`) and commit the file. Vercel applies it from the repository, not from the build.
- `app/sitemap.ts` and `app/robots.ts` cover every route; nothing is set to noindex.
- Event JSON-LD is rendered on the five event pages by `components/EventJsonLd.tsx` from the dates and venues printed on those pages; ticket offers read `NEXT_PUBLIC_TICKETMASTER_URL`.
- Icons and the Open Graph image are generated from `public/assets/logo-culturebowl.png` by `npm run icons`.
- `app/not-found.tsx` is the 404 page (exported as `out/404.html`).

## Layout approach

Desktop (1024px and up) uses the 1440px artboards; below that the 390px artboards. Between
the two artboard widths everything is fluid: content sits in a 1440px max-width frame,
grids use fractional columns, and the Home hero scales from a unit `--u` that equals 1px at
1440 and shrinks with the container. Above 1440 the content is centred and backgrounds bleed.

The base stylesheet is wrapped in `@layer cb2`, so page modules always override it.

## Images

`public/assets` is the design export as delivered. `public/assets/r` holds resized WebP
candidates generated by `node scripts/resize.js` (sharp): stones and logos for `srcset`
on the plain `<img>` elements, and phone-sized hero backgrounds that `lib/imageLoader.ts`
(the `next/image` custom loader for the static export) serves below 1440px. Desktop always
gets the original files. Re-run the script after replacing any of those source images.

## Video

The About hero plays an aerial pass over Atlanta behind the design's still image:
`public/assets/video/atlanta-aerial-1280.mp4` (3.2 MB) on desktop and the 720px cut (1 MB) on
phones, both encoded from the delivered 16 MB master with ffmpeg (H.264, CRF 33, no audio,
faststart). `components/BgVideo.tsx` starts it after the page's load event, skips it under
prefers-reduced-motion or Save-Data, and fades it in once it is actually playing, so the still
remains the first paint and the fallback.

## Verification scripts (`scripts/`)

They need the design folder and the export served locally:

```bash
python3 -m http.server 4100 --directory design &
npx serve out -l 4200 &
node scripts/compare.js            # every artboard vs its route at 1440 and 390, prints mismatch %
node scripts/compare.js about      # one comparison (id substring)
node scripts/deltas.js about-d     # per-text position deltas between artboard and route
node scripts/behaviors.js          # countdown, hover labels, nav states, menu focus trap, ticket links
node scripts/forms.js              # form submissions against a build with NEXT_PUBLIC_FORM_ENDPOINT set (:4202)
node scripts/fluid.js              # horizontal overflow check across viewport widths
```

`NEXT_PUBLIC_RELATIVE_PREVIEW=true npm run build` followed by `node scripts/preview-export.js <dir>`
produces a copy of the export that runs from any folder or base path without server routing
(page links load their `.html` files, all URLs relative). It is for hosted previews only.
Building again with `NEXT_PUBLIC_HEADLINER_ANNOUNCED=true` and running the script with `--announced`
merges that home page in as `index-announced.html` and adds a hero switch to both home pages.

`scripts/support.js` is a small stand-in for the design tool's template runtime so the
artboards render their `renderVals()` data during comparison. It is never shipped.
